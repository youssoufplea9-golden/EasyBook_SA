## 1. Project Overview

**EasyBook** is a professional digital bookstore platform that supports three distinct user roles: **Admins**, **Editors**, and **Clients (Readers)**. It features:

-  **JWT-based authentication** with access + refresh token rotation
- **Role-Based Access Control (RBAC)** with a pending-approval workflow for editors
- **ISBN Auto-fill** via Open Library API (no API key required) with Google Books fallback
- **Dynamic theming** — light/dark mode + 5 colour palettes, persisted in localStorage
- **Full i18n** — English, French, Turkish with fluent translations
- **Docker-ready** — one command to spin up the entire stack
- **Async Python** — FastAPI + asyncpg for high-throughput database access
- **Strict Layered Architecture** — Controllers → Services → Repositories

## 2. Architecture

```
┌─────────────────────────────────────────────────────┐
│                   PRESENTATION LAYER                │
│         React 18 + Vite + Tailwind CSS              │
│   Pages ─ Components ─ Routes ─ Contexts ─ Store   │
└──────────────────────┬──────────────────────────────┘
                       │ HTTP/JSON (Axios + JWT)
┌──────────────────────▼──────────────────────────────┐
│                  BUSINESS LAYER                     │
│              FastAPI Controllers                    │
│         AuthService │ BookService │ AdminService    │
│              BookLookupService (ext. API)           │
└──────────────────────┬──────────────────────────────┘
                       │ SQLAlchemy ORM (async)
┌──────────────────────▼──────────────────────────────┐
│                 PERSISTENCE LAYER                   │
│       UserRepository │ BookRepository               │
│            PostgreSQL 16 via asyncpg                │
└─────────────────────────────────────────────────────┘
```

### Backend Layering

| Layer | Responsibility | Files |
|---|---|---|
| **Controller** | HTTP routing, request/response parsing | `api/controllers/` |
| **Middleware** | JWT validation, RBAC dependency injection | `middlewares/auth_middleware.py` |
| **Service** | Business rules, orchestration | `services/` |
| **Repository** | DB queries only, no business logic | `repositories/` |
| **Model** | SQLAlchemy ORM definitions | `models/models.py` |
| **Schema** | Pydantic v2 request/response DTOs | `schemas/schemas.py` |

### Frontend Layering

| Layer | Responsibility |
|---|---|
| **Pages** | Route-level components (Admin / Editor / Client) |
| **Components** | Reusable UI building blocks |
| **Services** | Axios API calls (`src/services/api.ts`) |
| **Store** | Zustand auth state (persisted) |
| **Contexts** | React Context for ThemeProvider |

## 5. Quick Start (Docker)

```bash
# 1. Clone / unzip the project
cd easybook

# 2. Copy and edit environment files
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
# Edit SECRET_KEY in backend/.env (see §7)

# 3. Launch everything
docker compose up --build

# 4. Open the app
#    Frontend:  http://localhost:5173
#    API Docs:  http://localhost:8000/docs
```

The first startup will:
- Run all Alembic migrations automatically
- Seed the default admin account (`admin@easybook.io / Admin@1234`)

## 6. Manual Installation

### Prerequisites

- Python 3.12+
- Node.js 20+
- PostgreSQL 16 running locally

### Backend

```bash
cd backend

# Create virtual environment
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Configure environment
cp .env.example .env               # then edit DATABASE_URL, SECRET_KEY

# Run migrations
alembic upgrade head

# Start the API server (with hot-reload)
uvicorn app.main:app --reload --port 8000
```

### Frontend

```bash
cd frontend

# Install dependencies
npm install

# Configure environment
cp .env.example .env               # VITE_API_BASE_URL=http://localhost:8000/api/v1

# Start the dev server
npm run dev
```

### Automated bootstrap

```bash
# Run once from the project root (requires Docker for PostgreSQL)
chmod +x setup.sh
./setup.sh
```

## 7. Environment Variables

### `backend/.env`

| Variable | Description | Example |
|---|---|---|
| `DATABASE_URL` | Async SQLAlchemy URL | `postgresql+asyncpg://user:pw@localhost/db` |
| `DATABASE_URL_SYNC` | Sync URL (Alembic only) | `postgresql://user:pw@localhost/db` |
| `SECRET_KEY` | JWT signing key (**must change**) | `openssl rand -hex 32` |
| `ALGORITHM` | JWT algorithm | `HS256` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Access token TTL | `60` |
| `REFRESH_TOKEN_EXPIRE_DAYS` | Refresh token TTL | `7` |
| `FIRST_ADMIN_EMAIL` | Seeded admin email | `admin@easybook.io` |
| `FIRST_ADMIN_PASSWORD` | Seeded admin password | `Admin@1234` |
| `OPEN_LIBRARY_API_URL` | Open Library base URL | `https://openlibrary.org` |
| `GOOGLE_BOOKS_API_KEY` | Optional Google Books key | _(leave empty to use Open Library only)_ |
| `ALLOWED_ORIGINS` | CORS origins (comma-separated) | `http://localhost:5173` |

> **Security:** Generate a strong secret key before any deployment:
> ```bash
> openssl rand -hex 32
> ```

|---|---|---|
| `VITE_API_BASE_URL` | Backend API base URL | `http://localhost:8000/api/v1` |

## 8. API Documentation

Interactive docs are available at **`http://localhost:8000/docs`** (Swagger UI) and **`http://localhost:8000/redoc`** (ReDoc) when the server is running.

### Authentication Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| `POST` | `/api/v1/auth/register/client` | ❌ | Register a new reader (immediately active) |
| `POST` | `/api/v1/auth/register/editor` | ❌ | Register an editor (status: PENDING) |
| `POST` | `/api/v1/auth/login` | ❌ | Obtain access + refresh tokens |
| `POST` | `/api/v1/auth/refresh` | ❌ | Rotate token pair using refresh token |
| `GET`  | `/api/v1/auth/me` | ✅ Any | Get current user profile |

### Books Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| `GET`  | `/api/v1/books` | ✅ Any | Advanced catalog search (q, author, genre, category, language, dates, pagination) |
| `GET`  | `/api/v1/books/{id}` | ✅ Any | Get single book detail |
| `POST` | `/api/v1/books` | ✅ Editor/Admin | Create a new book |
| `PATCH`| `/api/v1/books/{id}` | ✅ Editor/Admin | Update a book |
| `DELETE`| `/api/v1/books/{id}` | ✅ Editor/Admin | Delete a book |
| `GET`  | `/api/v1/books/editor/my-books` | ✅ Editor | List authenticated editor's books |
| `GET`  | `/api/v1/books/isbn/{isbn}` | ✅ Editor | Auto-fill metadata from Open Library / Google Books |

### Admin Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| `GET`  | `/api/v1/admin/editors/pending` | ✅ Admin | List all pending editors |
| `POST` | `/api/v1/admin/editors/{id}/approve` | ✅ Admin | Approve an editor |
| `POST` | `/api/v1/admin/editors/{id}/reject` | ✅ Admin | Reject an editor |
| `GET`  | `/api/v1/admin/users` | ✅ Admin | List all users (paginated) |
| `PATCH`| `/api/v1/admin/users/{id}/status` | ✅ Admin | Update any user's status |

### Example: Login Request

```bash
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "admin@easybook.io", "password": "Admin@1234"}'
```

### Example: ISBN Lookup

```bash
curl -X GET http://localhost:8000/api/v1/books/isbn/9780743273565 \
  -H "Authorization: Bearer <your_token>"
```

### Example: Search with Filters

```bash
curl "http://localhost:8000/api/v1/books?q=gatsby&genre=Fiction&page=1&page_size=12" \
  -H "Authorization: Bearer <your_token>"
```

## 9. Role Guide

### Admin

**Login:** `admin@easybook.io` / `Admin@1234` (seeded automatically)

**Capabilities:**
- View the Admin Dashboard with live statistics
- Review all pending editor applications
- **Approve** or **Reject** editor accounts with one click
- Browse and delete all books in the catalog
- View all users with their roles and statuses

**Route:** `/admin`

---

### Editor

**Registration:** `/register` → select "Editor"

**Approval workflow:**
1. Editor registers → status set to `PENDING`
2. Editor sees a professional "Awaiting Approval" screen if they attempt to log in
3. Admin approves → editor status becomes `ACTIVE`
4. Editor can now log in normally and access their dashboard

**Capabilities (once approved):**
- View their personal book dashboard with stats
- **Create books** with ISBN auto-fill (fetches title, author, genre, cover, description automatically from Open Library)
- Edit and delete their own books
- Toggle books between Published / Draft

**Route:** `/editor`

---

### Client (Reader)

**Registration:** `/register` → select "Reader" (immediately active)

**Capabilities:**
- Browse the full book catalog in a responsive grid layout
- **Advanced search:** keyword (title/author/description/ISBN), author, genre, category, language, published date range
- Paginated results with smart page navigation
- View full book detail pages

**Route:** `/catalog`

## 10. Theming System

EasyBook implements a fully dynamic, dual-axis theming system:

### Light / Dark Mode

- Toggled via the **Moon/Sun** button in the top navigation bar
- Uses Tailwind's `dark:` class strategy applied to `<html>`
- Persisted in `localStorage` under `easybook:theme:mode`
- Respects `prefers-color-scheme` on first visit
- Smooth 300ms CSS transitions on background and text colours

### Colour Palettes

Five accent palettes are available:

| Palette | Key | Preview |
|---|---|---|
| Ocean Blue | `blue` | Default |
| Emerald | `emerald` | Green |
| Rose | `rose` | Pink/Red |
| Purple | `purple` | Violet |
| Amber | `amber` | Gold |

- Switched via the **Palette** button in the top navigation bar
- Implemented via CSS custom properties (`--color-primary-*`) in `globals.css`
- A `data-palette` attribute on `<html>` activates the correct variable set
- All Tailwind `primary-*` utility classes reference these variables
- Persisted in `localStorage` under `easybook:theme:palette`

### Implementation

```
src/contexts/ThemeContext.tsx  ← React Context, state management, localStorage sync
src/styles/globals.css         ← CSS custom property definitions for all palettes
tailwind.config.js             ← primary-* colours mapped to CSS variables
```

## 11. i18n System

Three fully translated locales with high-quality, fluent translations:

| Code | Language | File |
|---|---|---|
| `en` | English | `src/i18n/locales/en.json` |
| `fr` | Français | `src/i18n/locales/fr.json` |
| `tr` | Türkçe | `src/i18n/locales/tr.json` |

- **Detection order:** `localStorage` → browser `navigator.language`
- **Switcher:** Globe icon in the top navigation bar, dropdown with flag + name
- **Library:** `i18next` + `react-i18next` + `i18next-browser-languagedetector`
- **Persistence:** Selected language stored in `localStorage`

Adding a new language:
1. Create `src/i18n/locales/xx.json` (copy `en.json` structure)
2. Add to `resources` in `src/i18n/index.ts`
3. Add to the `LANGUAGES` array in `LanguageSwitcher.tsx`

## 12. Database Schema

### `users` table

| Column | Type | Notes |
|---|---|---|
| `id` | UUID | Primary key |
| `email` | VARCHAR(255) | Unique, indexed |
| `full_name` | VARCHAR(255) | |
| `hashed_password` | VARCHAR(255) | bcrypt |
| `role` | ENUM | `ADMIN`, `EDITOR`, `CLIENT` |
| `status` | ENUM | `ACTIVE`, `PENDING`, `REJECTED`, `SUSPENDED` |
| `is_active` | BOOLEAN | Soft disable |
| `created_at` | TIMESTAMPTZ | Auto |
| `updated_at` | TIMESTAMPTZ | Auto |

### `books` table

| Column | Type | Notes |
|---|---|---|
| `id` | UUID | Primary key |
| `isbn` | VARCHAR(20) | Unique, nullable, indexed |
| `title` | VARCHAR(500) | Indexed |
| `author` | VARCHAR(255) | Indexed |
| `description` | TEXT | Nullable |
| `cover_image_url` | VARCHAR(1000) | Nullable |
| `genre` | VARCHAR(100) | Nullable, indexed |
| `category` | VARCHAR(100) | Nullable |
| `language` | VARCHAR(50) | Nullable |
| `publisher` | VARCHAR(255) | Nullable |
| `published_date` | VARCHAR(20) | Nullable (flexible format) |
| `page_count` | INTEGER | Nullable |
| `price` | VARCHAR(20) | Nullable |
| `is_published` | BOOLEAN | Default `true` |
| `editor_id` | UUID FK | References `users.id` CASCADE DELETE |
| `created_at` | TIMESTAMPTZ | Auto |
| `updated_at` | TIMESTAMPTZ | Auto |

### Status / Role Logic

```
Registration (Client)  →  status: ACTIVE   (can login immediately)
Registration (Editor)  →  status: PENDING  (blocked until admin approves)
Admin approves editor  →  status: ACTIVE   (can now login)
Admin rejects editor   →  status: REJECTED (sees rejection screen)
```
